# AUDIT AWAL — KONDISI PROJECT & KELAYAKAN EXTERNAL TTS

**Tanggal:** 2026-11-08
**Lingkup:** audit kondisi repository, environment, akses jaringan, dan kelayakan 4 kandidat engine TTS (VoxCPM 2, XTTS-v2, OpenVoice V2, RVC) — **belum** membangun seluruh aplikasi.
**Metode:** setiap pernyataan di bawah ini berasal dari pengukuran langsung di sandbox (bukan dari dokumentasi vendor). Perintah yang bisa diulang tersedia di akhir dokumen.

> **Ringkasan satu paragraf.** Repository awalnya kosong (1 file, 1 commit). Environment: 2 vCPU, RAM 3.8 GB, disk 20 GB, **tanpa GPU**. npm, PyPI, dan GitHub (source) dapat diakses — tetapi **HuggingFace, ModelScope, dan GitHub release-assets diblokir**. Konsekuensinya: **tidak ada satu pun checkpoint model TTS neural yang bisa diunduh di sandbox ini**, termasuk keempat kandidat wajib. Kode engine bisa dipasang; bobotnya tidak. Satu-satunya engine yang benar-benar berjalan offline adalah **eSpeak NG** yang berhasil saya build dari source (Bahasa Indonesia terverifikasi, RTF 0.004) — tetapi kualitasnya formant/robotik, **tidak layak untuk dialog final**. Rekomendasi: jadikan pipeline siap-adapter sekarang, dan jalankan engine produksi (VoxCPM 2) di mesin yang bisa mengakses bobot, lalu hubungkan lewat adapter `http-remote` yang sudah diimplementasikan.

Temuan penting dan solusinya:

1. **apt tidak bisa dipakai.** Mirror `deb.debian.org` tidak dapat dijangkau, `ffmpeg` tidak punya kandidat instalasi. → ffmpeg/ffprobe dipasang lewat paket npm `@ffmpeg-installer/*` yang **membawa binary di dalam tarball npm** (tanpa unduhan tambahan). Terverifikasi jalan: ffmpeg `N-47683-g0e8eb07980` (build 2018), ffprobe `N-66595`. Catatan: versi ini tua — cukup untuk WAV/MP3 dan mux MP4, tetapi harus diuji ulang untuk filter render yang kompleks.
2. **Chromium tidak ada.** `@sparticuz/chromium` **berhasil dipasang dari npm** (19 paket) dan dipakai nanti untuk renderer. Ini penting: karena `ffmpeg-static` gagal (postinstall-nya mengunduh dari GitHub release-assets yang diblokir), jalur ffmpeg yang dipakai adalah `@ffmpeg-installer`.
3. **cmake/ninja tidak ada.** Dipasang dari **wheel PyPI** (`pip install cmake ninja` → cmake 4.4.4, ninja 1.13) ke dalam `.tools/py`. Ini yang memungkinkan build eSpeak NG (§5).
4. **TLS interception.** `fetch()` bawaan Node gagal dengan `UNABLE_TO_VERIFY_LEAF_SIGNATURE` untuk github.com, padahal `curl` berhasil. Penyebab: proxy TLS sandbox memakai CA di system store yang tidak ada di bundle Node. **Jangan menonaktifkan verifikasi sertifikat**; saya buat `scripts/lib/net.mjs` yang membangun trust list (root Node + CA sistem + `/usr/local/share/ca-certificates/e2b-ca.crt`).

## 8. Engine alternatif yang benar-benar diuji

### 8.1 eSpeak NG — BERHASIL (tier: smoke-test only)

* Build dari tarball `codeload.github.com` + cmake/ninja dari PyPI: **±25 detik**, static, tanpa GPU.
* Indonesian voice `id`: **terverifikasi ada** (`--voices=id`).
* Benchmark nyata (kalimat audition brief, 79 karakter):

| Metrik | Nilai |
|---|---|
| Durasi audio | **7,59 s** @ 22 050 Hz mono 16-bit PCM |
| Waktu generate | **31 ms** |
| RTF | **0,0041** (≈245× realtime) |
| RAM | ~60 MB |
| Ukuran output | 335 KB WAV |

* **Kelemahan:** sintesis formant → robotik, prosodi datar, tidak memiliki "kepribadian" karakter. **Layak untuk:** uji pipeline, timing subtitle, placeholder dialog, CI. **Tidak layak untuk:** audio final yang tayang.
* Lisensi GPL-3.0 — aman untuk pemakaian internal (tidak mendistribusikan binary), tetapi harus dicatat.

### 8.2 Kandidat lain yang diperiksa dan ditolak

| Kandidat | Alasan ditolak |
|---|---|
| `espeakng` (PyPI) | hanya wrapper Python; binary eSpeak NG tidak disertakan |
| `piper-tts` 1.8.0 (wheel 34 MB, GPL-3.0) | kode OK, tetapi voice ONNX Indonesia ada di HuggingFace → diblokir |
| `sherpa-onnx` 2.0.1 | runtime baik, model VITS/MMS ada di HF & GitHub release-assets → diblokir |
| `melotts`, `kokoro-onnx` | checkpoint dari HF → diblokir |
| `edge-tts`, `gTTS` | butuh koneksi ke layanan Microsoft/Google (diblokir) + isu ToS untuk konten anak yang dipublikasikan |
| TTS internal agen | **tidak dapat dipanggil dari CLI/CI** (hanya dari sesi chat) → tidak reproducible, tidak bisa jadi engine produksi. Tidak dipakai, tidak di-fallback diam-diam |

### 8.3 `http-remote` — jalur produksi yang realistis

Karena studio ini CPU-only dan tidak punya akses bobot, arsitektur yang benar adalah: **engine berat dijalankan di tempat bobot itu ada**, studio mengorkestrasi lewat HTTP.

Kontrak v1 (sudah diimplementasikan di `audio/engines/adapters/http-remote.mjs`):

```
POST {TTS_HTTP_ENDPOINT}
{ "text": "...", "speakerId": "...", "language": "id", "params": {...}, "format": "wav" }
→ 200, body audio/wav (PCM 16-bit)
   header opsional: X-Engine-Version, X-Model-Version, X-Sample-Rate
→ non-2xx: { "error": "..." }
```

Status: **terimplementasi, belum diverifikasi** (tidak ada server di sandbox). Ini dinyatakan jujur, bukan diklaim sebagai fitur selesai.

## 9. Rekomendasi TTS utama

1. **Engine produksi (target): VoxCPM 2 via `http-remote`.**
   Jalankan VoxCPM 2 di mesin/VM yang bisa mengakses HuggingFace/ModelScope (RAM ≥ 8–16 GB, GPU ideal), bungkus dengan kontrak di §8.3, lalu isi `TTS_HTTP_ENDPOINT`. Voice identity disimpan di registry studio — **bukan** bergantung pada mesin tersebut.
2. **Engine produksi (alternatif lokal): VoxCPM 2 in-process** — hanya jika (a) bobot diletakkan di disk (`VOXCPM_WEIGHTS_PATH`), (b) RAM dinaikkan ≥ 8 GB, (c) lisensi diverifikasi untuk komersial. Adapter sudah siap dan akan otomatis "weights-present-unverified" lalu tetap menolak sampai benchmark dijalankan.
3. **Engine smoke-test/CI: eSpeak NG** — sudah berjalan, dipakai untuk menguji pipeline & timing. **Ditolak untuk audio tayang** (dikunci di `config/studio.config.json → voicePolicy.productionEngines`).
4. **Pembanding: XTTS-v2** — hanya untuk A/B lokal, dan **tidak** untuk episode komersial sampai lisensi CPML diklarifikasi.
5. **Pasca-proses: OpenVoice V2 / RVC** — ditunda sampai ada TTS Indonesia yang bekerja.

## 10. Rekomendasi voice conversion pendukung

* Untuk saat ini: **tidak ada**. Voice conversion tanpa engine TTS dasar tidak menghasilkan dialog.
* Urutan yang benar di masa depan: `TTS Indonesia → (opsional) OpenVoice/RVC untuk warna timbre → master WAV`.
* Peringatan: RVC/OpenVoice tidak boleh dipakai untuk meniru suara orang nyata atau suara anak nyata tanpa izin tertulis.

## 14. Perintah untuk mereproduksi audit ini

```bash
npm run bootstrap        # dependency + build eSpeak NG dari source
npm run doctor           # host, toolchain, jaringan, engine → manifests/environment.json
npm run voice:engines    # matriks engine dengan probe langsung
npm run voice:audition -- --character bobby   # 3 kandidat suara, teks identik
npm run assets:manifest  # checksum seluruh aset
npm run validate         # schema + checksum + voice gate
npm test                 # 10 unit test
```

Uji pipeline suara end-to-end (bukan produksi):

```bash
npm run voice:generate -- --episode ep-001 --engine espeak --allow-unapproved --speaker "id+m3" --reflow
```

Hasil terukur: 5 baris dialog, 31,13 s audio total, RTF rata-rata **0,0051**, scene otomatis di-retime agar audio muat.

## 15. Yang akan mengubah kesimpulan ini

1. **Berikan akses egress ke `huggingface.co`** (atau taruh bobot VoxCPM 2 di disk sandbox) → P2 benchmark bisa langsung dijalankan, dan pertanyaan "apakah VoxCPM 2 benar-benar bagus untuk Bahasa Indonesia" bisa dijawab dengan data, bukan klaim.
2. **Naikkan RAM ke ≥ 8 GB** → inference lokal CPU mulai realistis untuk kalimat pendek.
3. **Sediakan satu mesin dengan GPU / akses HF** → jadikan host `http-remote`; ini jalur tercepat menuju suara produksi tanpa mengubah studio.
4. **Klarifikasi lisensi VoxCPM** (file `LICENSE` di repo OpenBMB) → prasyarat komersial.

Tanpa salah satu dari empat hal di atas, **kualitas suara produksi tidak dapat dicapai di environment ini** — dan itu dinyatakan di depan, bukan ditutupi dengan TTS internal atau placeholder yang diklaim selesai.
